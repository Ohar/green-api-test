# Проверки специалистов

12 октября 2026 года. Работу консультировали четыре отдельных агента.

## Юзабилити

Реализован и проверен интерфейс для desktop/mobile. По замечаниям:

- Добавлены подписи полей, видимый focus и текстовые ошибки.
- На мобильном ввод не мельче 16px, есть возврат к списку чатов.
- Автопрокрутка не мешает чтению предыдущих сообщений.
- Обработаны Enter, Shift+Enter и ввод через IME.
- Повтор только вставляет текст в черновик; неопределённая отправка
  сопровождается предупреждением о возможном дубле.
- Ограничение истории объясняется до подключения и в интерфейсе чата.
- Статус соединения виден также в мобильном списке диалогов.
- Быстрый ответ в ту же секунду остаётся после исходящего сообщения.

## Безопасность

Исправлено по аудиту:

- Адрес API ограничен проверенными HTTPS-хостами, redirect запрещён.
- Cookies, persistent storage и логирование токена не используются.
- Production CSP исключает inline-код и локальные dev-подключения.
- При событии потери авторизации отправка блокируется до завершения ACK.
- Ошибка ACK не отменяет терминальное прекращение работы.
- Потеря авторизации требует новой локальной сессии: кнопка повтора
  не переносит контакты/историю в переавторизованный аккаунт.

## Чистый код

Настроены React/TypeScript ESLint и требуемые ограничения форматирования.
Автоматическая проверка структуры требует публичный index.ts компонентов,
вынесенные модульные constants/helpers и импорт через публичный интерфейс.
По замечанию аудитора поздние события/ответы не заменяют превью более
свежего сообщения. Публикация отделена от обычного push и защищена
проверками версии тега, ветки и исходников в CI.

## Соответствие тестовому GREEN-API

Контракты сверены с Telegram-разделом официальной документации.
Исправлены/учтены:

- `checkAccount` перед отправкой по canonical `chatId`.
- Обработка `textMessage` и `extendedTextMessage`.
- `failed`/`noAccount` без `idMessage`, включая телефонный alias `@c.us`.
- Повторное уведомление после неуспешного ACK не дублирует текст.
- При постоянно повторяющемся receipt цикл останавливается.
- HTTP 200 с бизнес-ошибкой проверки номера не означает успех.
- Постановка сообщения в очередь не означает доставку.
- Превью обновляется и при получении накопленной старой очереди.
- Проверенный телефон сохраняется у чата, созданного входящим событием.
- Эхо уточняет время исходящей реплики, сохраняя порядок равных timestamps.

Проверка доставки с настоящим инстансом остаётся отдельным шагом приёмки:
учётные данные не предоставлялись. Автотесты используют подменённую сеть.
